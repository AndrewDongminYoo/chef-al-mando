# Chef al Mando

Chef al Mando는 작은 레스토랑의 셰프가 되어 제한된 재료, 작업대, 인력을 배치하고 주문의 우선순위를 조정하는 오프라인 2D 주방 경영 시뮬레이션입니다.
핵심 경험은 빠르게 탭하는 동작이 아니라, 준비와 지시가 맞아떨어져 주방의 병목이 해소되는 과정에서 나옵니다.

## 현재 상태

| 항목           | 상태                                                                                                                          |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 제품·기술 기준 | 블루프린트 v0.1을 2026-09-07에 확정했습니다.                                                                                  |
| 저장소         | M3 고정 영업 8개·메뉴 8종·엔딩과 캠페인 기록 저장을 연결했습니다.                                                             |
| 엔진           | Godot Standard(버전은 저장소 루트의 `.godot-version`이 소유), 같은 버전의 export template, Compatibility 렌더러를 사용합니다. |
| 마일스톤       | M1 최종 iPhone 빌드의 정상 동작을 승인했습니다. 양 플랫폼 전체 수용 기준은 Android 실기기 검증을 기다립니다.                  |
| 다음 단계      | M3 로컬 구현·검증을 완료했습니다. 사용자 5명 검증은 운영자가 테스트 준비 완료를 명시할 때까지 보류합니다.                     |

블루프린트가 확정되었다는 사실은 제품 방향과 기술 경계를 승인했다는 뜻입니다.
콘텐츠 수량, 가격, 성능 목표, 플레이테스트 기준을 이미 실측했거나 달성했다는 뜻은 아닙니다.

## 제품 약속

- iOS와 Android 휴대폰·태블릿을 위한 가로 화면 2D 탑다운 게임입니다.
- 영업은 실시간으로 진행하지만 언제든지 일시정지할 수 있습니다.
- 플레이어는 발주, 프렙, 설비 배치, 직원 담당, 주문 우선순위를 결정합니다.
- 손실과 지연에는 플레이어가 읽을 수 있는 원인이 있어야 합니다.
- 한 번 구매하면 시작부터 엔딩까지 오프라인으로 플레이할 수 있습니다.
- 광고, 인앱 결제, 에너지, 가챠, 접속 보상, 강제 계정, 서버, 멀티플레이, 클라우드 동기화는 v1 범위에 포함하지 않습니다.

## 핵심 플레이 루프

1. 예상 주문, 예산, 필수 목표를 확인합니다.
2. 메뉴, 재료, 프렙, 직원 담당, 설비 배치를 정합니다.
3. 영업 중 주문 우선순위와 담당을 조정하고 필요하면 주문을 취소합니다.
4. 마감 화면에서 손익, 제공률, 폐기, 지연 원인을 확인합니다.
5. 같은 영업을 재도전하거나 다음 시나리오로 진행합니다.

정답이 빠른 탭 하나로 수렴하면 핵심 설계를 다시 검토합니다.
같은 주문 조건에서도 우선순위와 배치 정책에 따라 결과와 병목 원인이 달라져야 합니다.

## v1 범위

| 구분 | 출시 기준                                          |
| ---- | -------------------------------------------------- |
| 공간 | 레스토랑 테마 1개, 주방 레이아웃 3종               |
| 진행 | 튜토리얼을 포함한 시나리오 8개, 마지막 영업과 엔딩 |
| 음식 | 메뉴 8종, 재료 12종 이내                           |
| 직원 | 동시 최대 4명                                      |
| 설비 | 최대 6개, 역할 4종                                 |
| 운영 | 발주, 프렙, 우선순위, 설비 배치                    |
| 상품 | 선불, 오프라인, 한국어·영어                        |

이 수량은 상한이자 초기 제작 목표입니다.
M2에서 재미와 제작 비용을 측정한 뒤 범위를 줄일 수 있습니다.
가격 6,600원은 검증 전 출발 가설이며 출시 가격이 아닙니다.

## 기술 방향

- Godot 4.x Standard와 typed GDScript를 사용합니다.
- Compatibility 렌더러로 시작하고 iOS와 Android 실기기에서 검증합니다.
- 시뮬레이션은 SceneTree 없이 실행할 수 있는 `RefCounted` 기반 객체로 구성합니다.
- 시뮬레이션 결과는 UI, 애니메이션, 렌더링 프레임 수, 실제 시계에 의존하지 않습니다.
- 게임 시간은 100ms 고정 tick으로 진행합니다.
- 정적 정의는 `Resource`에 두고 런타임 상태는 별도 객체에 둡니다.
- 엔진 수정, Rust FFI, ECS, 범용 프레임워크, 자체 콘텐츠 편집기는 검증 근거가 생기기 전까지 도입하지 않습니다.

## 마일스톤

| 단계 | 목표                                                                         |
| ---- | ---------------------------------------------------------------------------- |
| M0   | 양 플랫폼 실기기에서 빈 주방과 터치 UI를 실행합니다.                         |
| M1   | 직원 2명, 설비 4개, 메뉴 3개, 주문 20건으로 한 번의 300초 영업을 완주합니다. |
| M2   | 프렙·배치·우선순위의 재미와 콘텐츠 제작성을 사용자 5명으로 검증합니다.       |
| M3   | 시나리오 8개와 엔딩을 갖춘 완결형 콘텐츠를 만듭니다.                         |
| M4   | 저장·복원, 한국어·영어, 태블릿, 설정을 모바일 제품 수준으로 완성합니다.      |
| M5   | 서명 빌드와 스토어 자료를 포함한 출시 후보를 검증합니다.                     |

각 단계는 앞 단계의 통과 근거를 확인한 뒤 시작합니다.
M0~M1에는 우선 7 작업일을 배정하며, 통과 전에는 캠페인 확장, 브랜딩, 콘텐츠 자동화를 시작하지 않습니다.

## 로컬 실행과 검사

저장소 루트에서 다음 명령을 사용합니다.
`GODOT_BIN`은 `.godot-version`과 같은 버전이 설치된 절대 경로로 설정합니다.
검사 명령은 [구현 명세의 검증 명령 계약](docs/specs/m0-m1.md)이 소유합니다.

```bash
"$GODOT_BIN" --path .
```

`check.sh m0`는 엔진 버전, 리소스 import, M0 상태·안전 영역 검사를 수행합니다.
실기기 터치나 OS 생명주기 검증을 대신하지 않습니다.
`check.sh m1`은 고정 콘텐츠, 시뮬레이션 경계 규칙, 1배·4배 결정론과 주 화면 명령 경로를 검사합니다.

`check.sh m2`는 준비 명령·배치·분석과 기존 영업의 연결을 검사합니다.
`check.sh m3`는 캠페인 콘텐츠·순차 완주·해금·기록 보존·실제 장면 연결을 검사합니다.
M3 실행 명령은 [캠페인 명세](docs/specs/m3-campaign.md), 결과와 검증 한계는 [M3 검증 기록](docs/notes/m3-verification.md)에 있습니다.

```bash
bash scripts/check.sh m3
python3 tests/test_export_check.py
bash scripts/check-export.sh
```
