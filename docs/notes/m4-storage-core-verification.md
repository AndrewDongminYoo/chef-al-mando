# M4 저장 핵심 검증

## 범위와 기준

검증일은 2026-09-09이며 기준은 M3 머지 커밋 `7cb8f79d540dd70334e11e3d9bed363a4b68caaa`입니다.
PR #7의 `3325af04d3a1f196aaf3743d9bf75351a904b69a`에서 저장 핵심만 추출했습니다.
동일 파일의 기존 복원·파일 검사를 유지하고 명령과 초기 상태 관계를 보완했습니다.
화면 통합·설정·오디오와 그 수용 결과는 포함하지 않습니다.

## 실패 재현과 수정

실제 준비 API로 cold·hot 담당을 확정하고 tick 0·1·9, 작업 중, 마감 상태를 생성했습니다.
명령 없음, queue 대기, 실제 적용, sequence 간격, 적용한 명령과 아직 대기 중인 명령의 공존을 각각 검사합니다.

`build/check/split-history-red.log`는 782건 중 38건이 실패했습니다.
tick 0의 두 변조는 기존 검사에서 이미 거부했으며, 나머지 변조 19개는 직접 복원과 실제 JSON 파일 읽기에서 각각 잘못 허용되었습니다.
파일이 잘못 허용된 경우에는 백업 복구 성공 검사를 실행하지 않았습니다.
수정 후에는 이 19개 파일의 명시적 복구·원래 hash·백업 바이트 검사 57건도 실행했습니다.
초기 GREEN인 `split-history-green.log`는 839건·실패 0건입니다.
sequence 간격과 다른 명령이 대기 중인 적용 상태의 정상 복원 검사 16건을 추가한 최종 `split-core-final-m4-core.log`는 855건·실패 0건입니다.

위치 검사는 첫 주문 전이라는 일정 조건을 사용하며 tick 10을 하드코딩하지 않습니다.
queue의 고유 양수 sequence 개수가 `last_sequence`와 같을 때만 모든 제출 명령이 아직 대기 중이라고 판정합니다.
이때 초기 담당, 빈 보류 담당, 기본 우선순위, 취소되지 않은 상태를 요구합니다.
현재 값만으로 특정 과거 명령을 추정하지 않으며 전체 실행 이력 인증을 주장하지 않습니다.
기존 정상 경로 실패·소비·예약·작업 관계 회귀도 같은 핵심 suite에서 실행했습니다.

모든 Godot 실행은 `/Applications/Godot.app/Contents/MacOS/Godot`에 `--headless`를 전달했습니다.
M0–M3의 검사는 화면 노드와 상태를 읽으며 새 렌더링·좌표 입력 수용을 증명하지 않습니다.
기존 M3만 실행한 추출 전 baseline은 `split-base-m3.log`의 608건·실패 0건입니다.
최종 suite 로그는 `build/check/split-core-final-*.log`에 있습니다.

PCK는 실제 첫 주문을 만들고 명령 없는 `priority: 2`를 거부합니다.
정상 세션의 복원 직후와 마감 hash도 비교합니다.
`split-export-red.log`에서는 저장 핵심 완료 표시가 없는 fake engine을 성공으로 처리하던 검사가 실패했습니다.
수정 후 `split-export-green.log`에서 8건이 통과했습니다.
실제 PCK 결과는 `split-core-pck.log`에 있습니다.

앱 재실행과 설정·화면 연결은 두 번째 PR에서 검사합니다.
새 모바일 기기 쓰기와 화면 캡처는 수행하지 않았습니다.
Android 실기기·사용자 5명 검증 보류를 유지합니다.
