# 주방 화면과 공간 전략 실험 검증

작성일: 2026-09-10.
[승인 범위와 작업 계획](../plans/kitchen-operations-redesign.md)에 따라 화면을 보완하고 기존 `hot_queue`, `long_route` 복제본에서 공간 규칙을 비교했습니다.
기본 캠페인 리소스와 저장 버전은 변경하지 않았습니다.

## 판단

기본 `long_route`에서는 전담 배치가 전체 담당보다 제공 수를 늘렸지만, 기본 `hot_queue`에서는 줄였습니다.
담당 지정이 모든 맵에서 항상 손해라는 가설은 이 비교와 맞지 않습니다.
그러나 시험한 새 규칙 정책은 모두 기존 시나리오의 필수 목표에 미달했습니다.
두 맵에서 모두 새 밀집 배치의 전체 담당이 가장 많이 제공했으므로, 배치의 정답이 맵별로 달라졌다는 근거도 부족합니다.
따라서 공간 규칙은 실험 상태로 유지하며 캠페인 전체에 적용하지 않습니다.
직원 충돌과 전문화의 추가 여부는 결정하지 않았습니다.

## 비교 조건과 결과

각 시나리오의 주문표·seed·구매·공정 시간·직원 이동과 배정 규칙을 그대로 사용했습니다.
모든 비교는 `grill` 프렙 4개를 사용합니다.
`hot_queue`의 `grill` 기본 우선순위는 2, `long_route`는 기본값을 사용하며 영업 중 추가 우선순위 명령은 없습니다.
전체 담당은 `all`, 전담은 첫 직원을 냉식으로, 나머지를 온식으로 지정한 정책입니다.
기본 배치는 원본 위치이며 새 밀집 배치는 고정 설비를 유지한 채 가동 설비를 옮긴 정책입니다.
기존 밀집 기준은 기존 참조 정책의 이동·회전만 가져오고 구매·프렙·우선순위 조건을 맞췄습니다.

이동과 대기는 주문별 누적 tick을 10으로 나눈 초 단위입니다.
여러 주문을 합하므로 300초 영업 시간보다 클 수 있습니다.
담당 대기는 담당 부재와 해당 직원의 작업 중 대기를 포함합니다.
손익은 시뮬레이션의 정수 금액입니다.

| ------------ | ------------------- | ---- | ---: | ----: | ------: | -----------: | -----------: |

기존 밀집 기준을 새 규칙에 넣은 두 시도는 출고대 이동 때문에 `fixed_station`으로 거부됐습니다.
이 두 거부를 영업 실패나 제공 0건으로 계산하지 않습니다.
새 규칙에서 시험한 여덟 정책은 `hot_queue`의 제공 14건·손익 1500, `long_route`의 제공 17건·손익 2000을 동시에 달성하지 못했습니다.
이는 시험한 정책의 결과이며 모든 합법 배치의 불가능성을 증명하지 않습니다.

기본 `long_route`의 전담 정책은 설비 대기를 371.5초에서 209.1초로 줄였지만 담당 대기는 늘렸습니다.
이 결과는 설비 병목 완화와 담당 유연성 손실의 교환을 보여 줍니다.
새 밀집 배치에서는 전체 담당이 다시 우세하므로 담당 설정만으로 항상 이득을 얻는 구조는 아닙니다.
원인별 대기와 설비 예약 tick은 생성되는 `build/check/space-policy-comparison.json`에서 확인할 수 있습니다.
각 행은 실행한 전체 정책을 포함하며, 수락된 행은 준비 선택·집계·최종 상태 해시도 포함합니다.

## 화면과 규칙의 검증 범위

주방 요약·재고는 주문 패널의 스크롤 영역으로 옮겼습니다.
휴대폰은 상세를 접고 시작하며 주문 문구는 패널 안에서 줄바꿈합니다.
직원은 다음 이동 칸 또는 현재 작업대 방향에 맞는 네 방향 SVG를 표시합니다.
작업대 그림이나 애니메이션은 작업 완료 판정에 관여하지 않습니다.

공간 규칙은 작업 위치 중첩과 냉식대·화구의 직접 인접을 거부합니다.
두 맵 모두 출고대 위치·방향을 고정하고, `long_route`는 창고도 고정합니다.
준비 패널은 선택한 설비의 고정 여부와 각 이동·회전의 거부 이유를 입력 전에 표시합니다.
실험 복제본의 초기 데이터, 준비 명령, 선택 복원, 영업 세션 복원에서 같은 제약을 검사합니다.
기존 캠페인에서 만든 세션은 기존 규칙으로 계속 복원됩니다.

M2는 준비 예산의 실제 표시와 발주 후 갱신·영업 전환·재시작을 추가로 검사합니다.
M3는 두 실험의 정확한 고정 설비 집합과 원본 리소스의 고정 여부를 추가로 검사합니다.
준비 요약을 숨긴 기존 구현에서는 표시 검사 3개가 실패했고, `long_route`의 창고 고정을 제거한 임시 입력에서는 해당 고정 설비 검사가 실패했습니다.
렌더 검사는 준비 예산의 스크롤 영역 내 표시와 보드·주문 패널의 실제 뷰포트 경계를 포함해 48개 검사에서 실패 0을 확인했습니다.
출력 폴더가 없는 별도 체크아웃에서는 기존 검사의 PNG 저장 실패를 재현했고, 수정 후 직접 실행으로 폴더 생성과 이미지 저장을 확인했습니다.
영문 담당 변경 문구는 `Duty changes after step`으로 명확히 했으며 폰의 큰 글씨에서 두 줄로 표시되는 것을 확인했습니다.

자동 검사는 화면·규칙의 구현 근거이며 실제 기기 가독성이나 플레이어의 이해를 대신하지 않습니다.
이 변경본의 모바일 설치, 실기기 터치와 사람의 설명 가능성은 확인하지 않았습니다.

## 재현

저장소 루트에서 `.godot-version`과 일치하는 `GODOT_BIN`을 사용합니다.

```bash
bash scripts/check.sh m2
bash scripts/check.sh m3
"$GODOT_BIN" --path . --max-fps 60 --script tests/test_kitchen_screen.gd
"$GODOT_BIN" --path . --max-fps 60 --script tests/capture_product_polish.gd
"$GODOT_BIN" --path . --max-fps 60 --script tests/capture_space_experiment.gd
"$GODOT_BIN" --headless --path . --script tests/compare_space_policies.gd
"$GODOT_BIN" --path . --script tests/play_space_experiment.gd -- --scenario hot_queue --layout original --duties all
"$GODOT_BIN" --path . --script tests/play_space_experiment.gd -- --scenario long_route --layout clustered --duties dedicated
```

실험 실행기는 임시 설정을 사용해 실제 준비·영업 화면을 열며 캠페인 기록을 저장하지 않습니다.
시작 전에 배치를 바꿀 수 있고 영업 중 담당을 바꾼 뒤 마감 지표를 비교할 수 있습니다.
사람의 확인에서는 같은 맵의 기본·밀집 배치와 전체·전담을 바꾸고, 제공 수와 대기의 변화 이유를 설명할 수 있는지 확인해야 합니다.
