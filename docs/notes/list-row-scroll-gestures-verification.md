# 목록 행 스크롤 제스처 검증

작성일: 2026-09-14.
기준 명세는 [목록 행 스크롤 제스처](../specs/list-row-scroll-gestures.md)입니다.
구현 순서는 [구현 계획](../plans/list-row-scroll-gestures-implementation.md)에 있습니다.

## 현재 상태

대상 구현과 로컬 검증을 완료했습니다.
작업 시작 시 staged, unstaged와 untracked 변경은 없었습니다.

## 원인과 수정

영업 행과 주문 행은 기본 `Button` 입력 필터를 사용해 행 내부에서 시작한 포인터 입력을 막고 있었습니다.
빈 영역을 구성하는 컨테이너는 같은 입력을 막지 않았기 때문에 빈 공간에서 시작한 드래그만 스크롤 컨테이너에 도달했습니다.

두 종류의 행 버튼에만 `Control.MOUSE_FILTER_PASS`를 지정했습니다.
공통 버튼 생성기, 다른 입력 컨트롤과 스크롤 민감도는 변경하지 않았습니다.

## 실패 우선 확인

제품 코드를 수정하기 전에 실제 캠페인 장면과 실제 20개 주문 장면에 터치 드래그를 전달했습니다.
영업 행과 주문 행 모두 상위 `ScrollContainer`가 드래그 이벤트를 받지 못해 실패했습니다.
overflow가 있는 주문 목록의 스크롤 위치도 바뀌지 않았습니다.

최소 수정 뒤 두 행의 드래그 이벤트가 상위 컨테이너에 도달했습니다.
드래그 뒤 행 선택 횟수는 0이었고, 이어서 수행한 짧은 탭 뒤 선택 횟수는 1이었습니다.
Headless display server는 전달받은 터치 드래그를 모바일 관성 스크롤로 변환하지 않았으므로 자동 테스트는 스크롤 좌표가 아니라 입력 전달 경계를 검증합니다.

## 자동 검증

| 검사                  | 직접 읽은 속성                                                                                   | 결과                              |
| --------------------- | ------------------------------------------------------------------------------------------------ | --------------------------------- |
| `scripts/check.sh m3` | 실제 영업·주문 행의 드래그 전달, 드래그 중 선택 방지, 짧은 탭 1회와 기존 M3 동작을 확인했습니다. | `PASS: m3 checks=1109 failures=0` |
| Godot `--check-only`  | 프로젝트 스크립트와 리소스가 Godot 4.7.2에서 로드되는지 확인했습니다.                            | 종료 코드 0                       |
| `scripts/check.sh m4` | M4가 읽는 시뮬레이션, 저장, 현지화와 화면 계약을 확인했습니다.                                   | `PASS: m4 checks=1191 failures=0` |

M3 gate는 ADB의 `tcp:5037` daemon에 연결하지 못했다는 경고 1건을 출력했습니다.
M3 gate는 실패 0으로 끝났고 Android 실기기 상태를 읽지는 않았습니다.

## 남은 외부 검증

일상 사용 중인 iPhone과 Android 실기기에서 행 내부 드래그가 자연스럽게 목록을 움직이는지는 새 빌드 설치와 직접 관찰 전까지 확인되지 않았습니다.
이 로컬 검증 시점에는 기기 설치, 기기 실행, 커밋과 push를 수행하지 않았습니다.
