# M2 검증 기록

작성일: 2026-09-08.
기준 계약은 [M2 구현 명세](../specs/m2-preparation.md)이며 M1 기준 커밋은 `5388ebc`입니다.
검증·빌드 소스는 `7dc9188ddba7c16c50f0ef2c607faefaea5463bc`입니다.
현재 head의 CI·호스팅 리뷰와 새 조작의 운영자 확인은 해당 작업 후 갱신합니다.

## 1. 구현과 남은 수용 기준

원재료 발주, 메뉴별 프렙, 탭 기반 설비 이동·작업 방향 회전, 초기 담당, 마감 시간 분석, 마지막 준비로 재도전과 기본값 초기화를 구현했습니다.
기본 콘텐츠는 메뉴 3종·주문 20건·직원 2명·설비 4개를 유지합니다.
캠페인 확장, 중간 저장, 재고 이월은 추가하지 않았습니다.

로컬 규칙·화면·팩 검사는 아래 범위에서 통과했습니다.
M2 iPhone의 새 조작 확인, 현재 head의 호스팅 리뷰와 CI, 처음 접하는 사용자 5명의 관찰은 아직 완료되지 않았습니다.
Android 실기기 검증 보류는 기존 승인을 유지합니다.
코드 PR의 머지와 M2 전체 통과를 구분하고, 사용자 관찰이 없으면 M3에 착수하지 않습니다.

## 3. 실패를 먼저 확인한 경계

- 준비 기능이 없을 때 실제 준비 객체·콘텐츠 검사가 실패했습니다.
- 준비 재료를 영업에 연결하기 전에는 재고·예약·경로 선택·집계 검사 19개가 실패했습니다. `m2-rules-red.log`에 남아 있습니다.
- 큰 정수 발주가 예산 곱셈을 넘는 사례는 수량을 곱하기 전에 잔여 예산으로 한도를 검사해 차단했습니다.
- 공정을 건너뛴 데이터에서 기존 배열 반환이 타입 오류를 일으켰습니다. 반환 분기를 명시한 뒤 같은 데이터가 검증 오류로 거부됩니다. `m2-content-skip-red.log`와 `m2-content-green.log`에 남아 있습니다.
- 새 준비 명령 API가 없을 때 M2 화면 검사가 실패했습니다. `m2-ui-red.log`에 남아 있습니다.
- 시작 버튼을 안전 영역 밖으로 옮긴 렌더링 변형은 `M2 rendered start must remain in the safe area`로 실패했습니다. `m2-render-negative.log`는 실패 1개를 기록합니다.
- 이전 M1 전용 팩을 새 export 검사에 넣으면 `required converted export content is missing: res://content/m2_first_service.tres`로 실패합니다. `m2-export-missing-content-negative.log`에 남아 있습니다.
- 회전한 배치를 영업에 전달하지 않는 변형은 실제 제공 경로와 이동 시간 검사 2개가 실패했습니다. 확정 배치를 전달하면 경로가 6칸에서 8칸으로 늘고 이동 시간이 10 tick 증가합니다. `m2-rotation-transmission-red.log`와 `m2-rotation-green.log`에 남아 있습니다.

스크립트 오류가 있어도 테스트 집계가 완료 표지를 출력할 수 있으므로 실행 래퍼는 오류 문구와 종료 코드도 검사합니다.
실제 경로 실패 fixture는 이동 중 다음 타일을 막고, 예약 해제·소비 손실·중간 결과 위치·복구 후 제공을 확인합니다.
준비·이동·작업 시간 합계는 모든 고정 비교의 주문마다 종료 tick과 도착 tick의 차이에 일치합니다.

## 4. 승인한 선택 비교

다섯 실행은 seed 42, 같은 20건 주문, 발주 6600, 인건비 2000, 마감 tick 3000을 사용했습니다.
프렙은 구이 2개, 배치는 출고대 `(8, 5)`·작업 위치 `(8, 4)`, 우선순위는 구이 도착 다음 tick에 2로 변경한 경우입니다.
결합은 이 세 선택을 모두 사용합니다.
수치는 `test_m2_determinism.gd`의 실제 실행에서 읽었습니다.

모든 실행의 재료 부족·경로 없음 대기 tick은 0이며 담당 대기는 모두 담당 직원이 작업 중인 시간입니다.
주문별 누적 시간은 여러 주문을 합한 값이므로 영업 시간보다 클 수 있습니다.
설비별 시간에는 직원이 이동하는 동안의 예약도 포함합니다.

각 선택에서 시간 지표의 차이가 있었고 제공 수 또는 손익도 달라졌습니다.
프렙만 적용한 실행은 설비 대기가 늘고 제공 수가 줄었습니다.
이 한 fixture를 근거로 프렙이 항상 좋거나 나쁘다고 안내하지 않습니다.
작업 순서와 이동·설비 대기를 함께 비교할 수 있다는 근거로 사용합니다.
재미와 최적 전략을 입증한 결과는 아닙니다.

## 5. 아트와 로컬 리뷰

출처, 자산별 초안·검수 시간과 표시 보정은 [제작성 기록](m2-production.md)에 있습니다.
메뉴 데이터만 추가한 네 번째 메뉴는 기본 시나리오에 노출하지 않고 검증용 fixture로 포함했습니다.
export 설정은 테스트 스크립트·문서·빌드 산출물을 제외하면서 이 리소스 fixture를 포함합니다.

시뮬레이션·콘텐츠와 프레젠테이션의 독립 읽기 전용 검토에서는 차단 문제가 없었습니다.
단일 화면 비율에 한정된 검증 갭은 넓은 폰과 4:3 캡처로 보완했습니다.
적대적 교차 검토에서는 회전 좌표만 검사하고 실제 서비스 경로 변화를 검사하지 않은 갭을 찾았습니다.
위의 실패 변형과 회전 전후 경로 비교를 추가한 뒤 해당 차단 사유가 해소됐다는 승인을 받았습니다.
현재 head의 호스팅 코드·보안 리뷰 결과는 완료 후 갱신합니다.

변경 범위의 Trunk 검사는 56개 파일을 읽어 문제 없이 끝났습니다.
전체 CSpell 검사는 61개 파일에서 문제 0개였고, 알려지지 않은 단어를 넣은 변형에서 예상한 오류를 확인한 뒤 원래 바이트를 복구했습니다.
`AGENTS.md` 변경 후 수행한 `codex doctor --summary --ascii --no-color`는 경고 1개, 실패 0개를 보고했습니다.
별도의 참고 항목은 3개이며 업데이트 설정 관련 경고가 남아 있습니다.
이 진단은 로컬 Codex 환경의 참고 결과이며 게임 기능이나 CI 통과를 입증하지 않습니다.

Oracle의 개인 계정 `chef-al-mando` 프로젝트 조회는 `prep`, `placement`에 대해 `[no precedent found]`였습니다.
관련 없는 전역 도구 배치 선례는 게임 설계의 근거로 사용하지 않았습니다.
