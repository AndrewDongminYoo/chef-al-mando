# M5 출시 후보 준비 명세

작성일: 2026-09-09.
기준은 [블루프린트](../plans/PLAN.md)의 M5입니다.
운영자는 PR #8·#9 머지와 PR #7 종료 후 M5 진행을 요청했습니다.
이 요청에 따라 로컬 출시 준비를 시작하며, 보류 중인 Android 실기기·사용자 5명 검증과 M4 전체 수용 기준을 통과로 바꾸지 않습니다.

## 1. 이번 구현 범위

1. 설정에서 오프라인으로 읽는 라이선스 창을 추가합니다.
   실행 중인 Godot의 엔진 라이선스, 구성요소별 저작권·파일·라이선스와 각 라이선스 본문을 표시합니다.
2. 기존 export 검사에 실제 캠페인 8개 영업의 순차 완주·기록 재로드·엔딩 해제를 추가합니다.
   실행 코드는 PCK에서 읽고, 기준 운영 정책은 배포하지 않는 외부 검사 fixture에서 읽습니다.
3. 기존 M4 새 프로세스 검사를 두 PCK 사이에서도 실행합니다.
   이전 PCK의 이동·작업 중 저장을 새 PCK의 프로세스에서 읽고 복원 직후·마감 상태 해시, 설정과 기록을 비교합니다.
4. 자산 출처 목록, 스토어 문구 초안, 서명·다운로드·베타 수용 기록 형식을 작성합니다.

시뮬레이션 규칙, 저장 스키마, 앱 ID, 버전, 서명 계정, 콘텐츠 수량은 이 준비 작업으로 변경하지 않습니다.
스토어 등록·업로드·배포, 기기 쓰기와 GUI 실행은 별도 승인 대상입니다.
새 의존성을 추가하지 않습니다.

## 2. 자동 검증 계약

| 명령                                                                                                 | 직접 확인하는 속성                                                              |
| ---------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| `bash scripts/check.sh m5`                                                                           | 설정 버튼에서 열린 라이선스 본문, 엔진 고지·구성요소·라이선스 본문과 한·영 문구 |
| `bash scripts/check.sh m4`                                                                           | 기존 저장·복원·설정·화면 명령 회귀                                              |
| `python3 tests/test_export_check.py`                                                                 | export 실패, 파일·필수 완료 표시 누락을 실패로 처리                             |
| `bash scripts/check-export.sh`                                                                       | 새 PCK의 M1~M4 동작과 M5 캠페인 완주·라이선스 접근                              |
| `python3 tests/test_m4_restart.py`                                                                   | 같은 소스의 새 프로세스 복원·강제 종료·저장 교체 경계                           |
| `M4_WRITER_PACK=/absolute/old.pck M4_READER_PACK=/absolute/new.pck python3 tests/test_m4_restart.py` | 서로 다른 PCK의 새 프로세스 저장 호환성                                         |

모든 Godot 호출은 버전 조회를 포함해 `--headless`로 실행합니다.
엔진 버전은 `.godot-version`과 일치해야 합니다.
PCK 검사 완료 표시는 `PASS: exported M5 campaign ending and licenses`입니다.
기존 M3 기준 정책으로 각 시나리오의 실제 3000 tick 영업을 실행하고, 잠금 순서·목표·손익·재고·저장 후 재로드·엔딩을 확인합니다.
각 검사는 전용 임시 저장 경로를 사용합니다.
PCK 쌍은 둘 다 존재하고 SHA-256이 달라야 하며, 실행 경로는 소스가 없는 임시 디렉터리여야 합니다.
누락 fixture·틀린 저장 해시·누락 완료 표시가 실패하는 음성 검사를 유지합니다.

## 3. 실제 출시 수용 계약

로컬 headless 검사와 개발 서명은 출시 통과를 증명하지 않습니다.
아래 표를 실제 배포 후보마다 채웁니다.

| 항목      | 필수 증거                                                                                                       |
| --------- | --------------------------------------------------------------------------------------------------------------- |
| 빌드 식별 | 소스 커밋, 앱 ID, 표시 버전·빌드 번호, 엔진·템플릿 버전, 산출물 SHA-256, 서명 검증                              |
| 다운로드  | 승인한 배포 채널, 업로드한 빌드와 실제 받은 빌드 식별 일치                                                      |
| 오프라인  | 두 플랫폼에서 네트워크 차단 후 최초 실행부터 엔딩까지 수동 진행                                                 |
| 업데이트  | 기존 다운로드 빌드에서 기록·진행 중 영업·설정 생성, 삭제 없이 새 다운로드 빌드 설치, 동일 상태와 마감 결과 확인 |
| 모바일    | 기종·OS, 배경 전환·강제 종료·복귀, 한·영과 큰 글자, 폰·태블릿, 라이선스 마지막 문단까지 스크롤                  |
| 베타      | 운영자가 재개한 사용자 검증, 시도별 관찰·문제·수정 빌드·재검증 결과                                             |
| 출시 판단 | 발견한 차단 문제와 해결 근거, 남은 차단 문제 0건 확인                                                           |

데스크톱 PCK 호환성은 앱 샌드박스·서명·스토어 업데이트 경로를 검사하지 않습니다.
headless 완주는 렌더링·터치·실제 네트워크 차단을 검사하지 않습니다.
배포 채널, 출시 앱 ID·버전, Android 기준 기기, 지원 연락처·공개 개인정보 안내 주소는 아직 확정하지 않았습니다.
