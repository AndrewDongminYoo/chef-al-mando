# M4 저장 핵심 명세

## 범위

2026-09-09에 승인된 [M4 PR 분할](../plans/m4-pr-split.md)의 첫 구현 단위입니다.
기존 M3 화면에 영업 중 이어하기를 연결하기 전에 simulation 복원과 캠페인 파일의 세션 저장을 독립적으로 검증합니다.
원본 PR #7의 schema 2, 직접 snapshot 복원, 고정 tick과 콘텐츠·회계 규칙을 유지합니다.
화면·설정·번역·오디오·실기기 수용은 두 번째 PR의 범위입니다.

## 저장과 복원

`ServiceSim.export_state()`는 복원할 상태를 깊은 복사로 반환합니다.
표시 이름·파생 회계·일회성 이벤트는 저장하지 않습니다.
`ServiceSim.restore(data, state, preparation)`는 전체 검사를 통과한 새 객체만 반환합니다.
실패는 `accepted: false`와 `reason`으로 반환하고 원래 객체를 바꾸지 않습니다.

기존 ID·enum·시간·일정·소비·예약·직원·작업·경로·점유 지표 관계 검증을 보존합니다.
정상 경로 실패 뒤의 이동 진행도와 산출물 위치는 현재 상태만으로 과거 이력을 역산할 수 없습니다.
`no_route > 0`에 적용하는 기존 보행 가능 위치·작업·수거 경로 검증을 보존하며, 실패 이력이 없는 상태의 더 엄격한 관계 검사와 구분합니다.

`ServiceSession`은 시나리오, 준비 선택, simulation, 배속, 잔여 마이크로초를 묶습니다.
JSON 정수와 정확한 필드 구성을 검증하고 준비 선택으로 definitions와 초기 상태를 재구성합니다.
해금된 시나리오만 복원하며 새로운 PRNG나 외부 엔진 계층은 만들지 않습니다.

M4 도입 당시 `CampaignStore`의 schema 2는 `schema_version`, `content_version`, `sim_version`, `records`, `active_session`을 갖습니다.
2026-09-09에 승인한 [메뉴별 기본 우선순위](menu-priorities.md)는 새 쓰기를 schema 3으로 확장하며 schema 1·2 읽기를 유지합니다.
schema 1은 읽을 때 세션이 없는 것으로 해석하며 읽기만으로 파일을 다시 쓰지 않습니다.
records-only 쓰기는 기존 세션을 보존하고, 세션 저장은 기록과 세션을 함께 교체합니다.
임시 파일을 다시 읽어 검증하고 마지막 유효 백업을 보존합니다.
손상은 자동 초기화하지 않으며 명시적으로 백업 복구를 실행합니다.
알 수 없는 미래 버전의 주 파일과 백업을 덮어쓰지 않습니다.

## 명령과 초기 상태의 불변식

명령 queue의 sequence는 양의 정수이며 고유하고 `last_sequence` 이하입니다.
queue 길이가 `last_sequence`와 같으면 모든 sequence가 아직 queue에 있으므로 적용되거나 거부되어 제거된 명령이 없음을 증명할 수 있습니다.
명령을 제출하지 않은 `last_sequence == 0`도 이 조건에 포함됩니다.
sequence의 간격은 허용하므로, 길이가 다르다는 사실만으로 특정 명령이 적용됐다고 추정하지 않습니다.

| 상태에서 증명할 수 있는 조건  | 반드시 유지할 값                                                                      |
| ----------------------------- | ------------------------------------------------------------------------------------- |
| `schedule_cursor == 0`        | 직원의 현재·다음 위치는 준비 직후 위치와 같음                                         |
| `tick == 0`                   | 직원 전체 상태는 준비 직후 상태와 같음                                                |
| 모든 명령이 아직 queue에 있음 | 현재 담당은 준비에서 정한 담당과 같음                                                 |
| 모든 명령이 아직 queue에 있음 | `pending_duty`는 빈 값                                                                |
| 모든 명령이 아직 queue에 있음 | 주문 `priority`는 준비에서 정한 메뉴별 기본값과 같음. 이전 저장에 기본값이 없으면 `1` |
| 모든 명령이 아직 queue에 있음 | `cancelled` 주문이 없음                                                               |

첫 도착 tick `10`을 구현 조건으로 하드코딩하지 않습니다.
실제 tick 1 담당 변경, 자율 이동, 적용된 우선순위·보류 담당·취소, 다른 명령이 남아 있는 상태를 허용합니다.
적용한 명령의 전체 이력은 저장하지 않으므로 위 조건 밖의 모든 과거 실행을 인증한다고 주장하지 않습니다.
완전한 이력 인증을 요구하려면 명령 이력·호환성 계약을 별도로 승인해야 합니다.

## 검증

실제 준비 API에서 기본과 다른 담당을 선택한 뒤 simulation을 실행합니다.
tick 0·1·9, 주문 도착 이후 작업, 마감 상태에서 정상 복원을 확인합니다.
명령 없음·queue 대기·적용 완료·sequence 간격·다른 명령 대기를 구분합니다.
변조한 상태의 직접 복원 거부와 원본 객체 보존을 검사합니다.
같은 상태를 실제 JSON 주 파일에 기록하고 새 저장소 객체의 손상 판정·백업 복구·바이트 보존을 검사합니다.
정상 상태는 복원 직후와 이어서 마감한 상태의 hash를 비교합니다.

`m4-core`는 복원·세션·파일·명령 관계만 검사합니다.
전체 M4 화면 수용으로 해석하지 않습니다.
PCK 검사는 배포된 세션 복원 코드로 명령 없는 우선순위 변조를 거부하고 정상 복원의 직후·마감 hash를 확인합니다.

```bash
export GODOT_BIN=/Applications/Godot.app/Contents/MacOS/Godot
bash scripts/check.sh m4-core
bash scripts/check.sh m0
bash scripts/check.sh m1
bash scripts/check.sh m2
bash scripts/check.sh m3
python3 tests/test_export_check.py
bash scripts/check-export.sh
```

새 프로세스의 앱 재실행·설정 복원·화면 연결은 두 번째 PR의 전체 검증에 포함합니다.
