# 첫 사용자 플레이테스트와 가격 반응 검증

작성일: 2026-09-18.
상태: 2026-09-18 운영자가 명세 작성과 경쟁작 가격 앵커 조사를 승인했습니다.
사용자 5명 검증의 재개 자체는 [M2 명세](m2-preparation.md) §11의 운영자 선언이 있을 때 시작합니다.

## 1. 문제

출시 전 두 질문에 답할 근거가 저장소에 없습니다.

- 재미: 처음 접하는 사용자 기록은 0명입니다([M2 검증 기록](../notes/m2-verification.md) §6).
  사람의 체감 데이터는 운영자 본인의 플레이 2회이며, 둘 다 난이도·긴장감·전략 폭을 지적했습니다([AGENTS.md](../../AGENTS.md), [캠페인 운영 압력 검증](../notes/kitchen-pressure-verification.md)).
- 지불 의사: [블루프린트](../plans/PLAN.md) §10.1은 M2-13 사용자 5명 검증을 방향성 검증으로 한정하고 시장 수요나 결제 전환의 증거로 쓰지 않는다고 정했습니다.
  즉 기존 계약을 그대로 재개해도 6,600원이라는 가설에는 답이 나오지 않습니다.

콘텐츠 분량은 `content/campaign/scenarios/*.tres` 8개에서 실측했습니다.
모든 시나리오의 `closing_tick`은 3000이므로 영업 시간 합계는 1배속 40분, 4배속 10분입니다.
주문 합계는 184건이고, `prng_state`가 항상 `null`이므로 주문 일정·메뉴에 무작위성이 없습니다.
재플레이 훅은 시나리오별 최고 기록뿐이며 튜토리얼 시스템은 없고 `first_shift`의 브리핑 문장이 그 역할을 대신합니다.
운영자는 2026-09-18에 전체 클리어 시간이 몇십 분 수준인 점을 치명적인 위험으로 판단했습니다.
준비·재도전을 포함한 실제 플레이 시간은 사용자 없이 측정할 수 없으므로 `[UNKNOWN]`입니다.

정체성 결함도 같은 날 확인했습니다.
설비 역할은 `storage`·`cold`·`hot`·`pass` 네 가지이고, 원재료는 곡물·버섯·채소·단백질이라는 분류명이며, 8개 레시피는 모두 `pickup → prep → cook → serve`의 같은 선형 공정에서 소요 시간만 다릅니다.
`sim/` 전체에서 묶음 조리, 보온, 신선도, 플레이팅 같은 주방 고유 규칙은 없고, 유일한 주방 취향 규칙인 냉온 설비 인접 금지(`content/definitions.gd`)는 배치 제약입니다.
운영자는 재료와 작업대의 이름과 생김새만 바꾸면 어떤 산업에도 붙일 수 있는 특징 없는 게임이라는 점을 현재 가장 큰 문제로 판단했습니다.
이 결함은 코드 검사로 확정되므로 사용자 관찰은 결함의 존재가 아니라 플레이어가 그것을 느끼는지를 측정합니다.

## 2. 목표

한 번의 관찰 세션 설계로 세 가지를 함께 측정합니다.

1. 재미: M2-13의 자발적 재도전과 개선 가설.
2. 분량: 처음 접하는 사용자가 정해진 시간 안에 어디까지 진행하는지와 마감 후 분량 반응.
3. 가격: 6,600원 앵커에 대한 4단계 반응과 구매를 막는 이유.

결과는 방향성 증거이며 통계 증거나 시장 수요 증명이 아닙니다.
이 결과만으로 스토어 가격을 등록하거나 출시를 결정하지 않습니다.

## 3. 범위와 경계

- 참가자 모집, 연락, 일정, 동의는 운영자가 수행합니다.
  에이전트는 참가자에게 메시지를 보내거나 모집하지 않습니다([M2 명세](m2-preparation.md) §11 유지).
- 세션 기기와 설치본은 운영자가 정합니다.
  운영자의 일상 iPhone을 쓰면 세션 전 `campaign_records.json`과 `.backup`을 기기에서 복사하고, 앱 내 새 게임으로 시작하며, 세션 후 복원합니다.
  복사·설치·실행은 각각 사전에 알리고 승인받습니다([M5 검증 기록](../notes/m5-verification.md) §9의 절차).
- 배포 채널, 출시 앱 ID, TestFlight 여부는 이 명세가 결정하지 않습니다.
  대면 세션은 채널 결정 없이 실행할 수 있으므로 기본 형식으로 둡니다.
- 경쟁작 가격은 앵커를 정하는 자료이지 수요 증거가 아닙니다.
  조사 결과는 [경쟁작 가격 앵커](../notes/competitor-price-anchors.md)에 URL과 접근일을 붙여 기록합니다.
- 제품 코드, 시나리오, 가격 문구는 이 명세로 변경하지 않습니다.

## 4. 참가자

- 처음 접하는 사용자 5명입니다.
  운영자, 에이전트, 이 게임을 이미 본 사람은 세지 않습니다.
- 주 1회 이상 모바일 게임을 하는 사람을 모집하며, 경영·퍼즐·시뮬레이션 계열 경험자를 우선합니다.
- 개발자만 모집하지 않고, 운영자와 가까운 사람만 모집하지 않습니다.
- 기록에는 참가자 번호, 기종·OS, 평소 하는 게임 종류만 남기고 개인정보는 남기지 않습니다.

## 5. 세션 절차

세션당 플레이 40분과 질문 10분을 배정합니다.

### 5.1 사전 기록

빌드 식별을 먼저 기록합니다: 소스 commit SHA, 앱 ID, 표시 버전·빌드 번호, PCK SHA-256, 기기.
세션 전 캠페인 기록을 백업하고 앱 내 새 게임으로 시작합니다.

### 5.2 도입

규칙을 설명하지 않습니다.
"작은 식당 주방을 운영하는 게임입니다. 하고 싶은 대로 해 보세요."라는 한 문장만 전달합니다.
게임이 스스로 가르치는지가 측정 대상이므로 브리핑을 대신 읽어 주지 않습니다.

### 5.3 플레이 관찰

운영자는 관찰만 하고 질문에 답하지 않습니다.
참가자가 3분 이상 같은 곳에서 막히면 최소 힌트 한 번을 허용하고 그 시점과 내용을 기록합니다.
플레이 중에는 아무것도 묻지 않습니다.

참가자별로 다음을 기록합니다.

| 항목          | 내용                                                    |
| ------------- | ------------------------------------------------------- |
| 첫 준비 선택  | 발주, 프렙, 배치, 담당, 메뉴 우선순위                   |
| 시나리오 진행 | 시나리오별 시도 횟수, 통과 여부, 도달한 마지막 시나리오 |
| 시간 사용     | 첫 영업 시작까지 걸린 시간, 배속 사용, 일시정지 사용    |
| 자발적 재도전 | 지시 없이 같은 영업을 다시 시작했는지                   |
| 두 번째 선택  | 재도전에서 바꾼 준비 선택                               |
| 막힌 조작     | 반응하지 않았거나 이해하지 못한 화면과 시점             |
| 힌트          | 시점과 내용, 없으면 없음                                |
| 차단 문제     | 크래시, 진행 불가, 저장 이상                            |

### 5.4 마감 후 질문

플레이가 끝난 뒤 한 번만, 아래 순서로 묻습니다.
답은 참가자의 말 그대로 적은 뒤에 분류합니다.
게임이 마음에 들었는지를 주된 질문으로 묻지 않습니다.

1. 방금 무엇이 잘 안 됐고, 다음에는 무엇을 바꾸겠습니까?
2. 헷갈린 곳, 불공평하다고 느낀 곳, 지루했던 곳이 각각 있었습니까? 어디였습니까?
3. 이 게임은 영업 8개와 엔딩으로 끝납니다. 방금 속도로 보면 분량이 짧다, 적당하다, 길다 중 어느 쪽입니까? 이유는 무엇입니까?
4. 가격 카드를 보여 줍니다: 6,600원 한 번 결제, 광고·인앱 결제 없음, 오프라인.
   이 가격은 너무 싸다, 적절하다, 비싸다, 수용 불가 중 어느 쪽입니까? 이유는 무엇입니까?
5. 무엇이 구매를 막겠습니까?
6. 직접 가격을 정한다면 얼마입니까? (선택)
7. 이 게임을 친구에게 한 문장으로 설명한다면 뭐라고 하겠습니까?

가격 카드의 6,600원은 검증용 앵커이며 스토어 가격 결정이 아닙니다.
7번은 주방이라는 소재가 플레이 경험으로 전달됐는지를 재는 질문이므로, 답에 주방·요리·식당이 등장하는지와 어떤 규칙을 언급하는지를 그대로 기록합니다.

## 6. 결정 게이트

5명은 방향성 증거입니다.
게이트는 다음 작업의 방향을 정하며 통계적 결론을 주장하지 않습니다.

| 게이트       | 판정 조건                                                                                     | 통과 시                                                         | 미달 시                                                                                                        |
| ------------ | --------------------------------------------------------------------------------------------- | --------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| 재미 (M2-13) | 5명 중 3명 이상이 지시 없이 재도전하고 다음 준비에서 바꿀 선택과 이유를 설명                  | M2 통과 근거를 기록                                             | 코어 루프 재설계 명세를 먼저 작성하고 출시 준비를 진행하지 않음                                                |
| 분량         | 5명 중 3명 이상이 "짧다"라고 답하거나, 40분 안에 시나리오 3개 이상을 통과한 참가자가 3명 이상 | 현재 분량으로 다음 게이트 판단                                  | [블루프린트](../plans/PLAN.md) §4의 조항을 발동해 반복 숙련 목표 개선 또는 상품 규모 재판단을 별도 명세로 작성 |
| 가격         | 5명 중 3명 이상이 "적절하다" 또는 "너무 싸다"                                                 | 6,600원을 앵커로 유지하고 스토어 가격은 출시 결정에서 별도 확정 | "수용 불가"가 2명 이상이면 가격·범위를 재설계, "비싸다"가 다수이면 분량 게이트와 함께 판단                     |
| 튜토리얼     | 첫 영업에서 힌트가 필요했거나 목표를 이해하지 못한 참가자가 2명 미만                          | 현재 브리핑 유지                                                | 튜토리얼 구현 명세 작성                                                                                        |
| 정체성       | 5명 중 3명 이상이 §5.4의 7번 답에서 주방·요리·식당의 규칙이나 상황을 언급                     | 주방 고유 규칙 설계는 분량·재미 결과와 함께 우선순위를 정함     | 주방 고유 규칙 설계 명세를 다음 구현보다 먼저 작성                                                             |
| 차단 문제    | 크래시·진행 불가·저장 이상 0건                                                                | 계속                                                            | 수정 후 같은 절차로 재검증                                                                                     |

재미 게이트가 미달이면 나머지 게이트의 통과와 무관하게 출시 준비를 계속하지 않습니다.
분량과 가격 게이트가 함께 미달이면 콘텐츠 추가보다 상품 규모와 가격을 먼저 다시 판단합니다.
정체성 게이트는 §1의 결함 존재를 재확인하는 것이 아니라, 결함을 고치는 규칙이 플레이 경험에서 무엇을 바꿔야 하는지 정하는 자료입니다.

## 7. 기록 형식

결과는 `docs/notes/playtest-price-validation.md`에 기록합니다.

1. 빌드 식별과 세션 날짜.
2. 참가자별 관찰 표(§5.3)와 질문 원문 답변(§5.4).
3. 분류 집계: 재도전 수, 분량 반응 분포, 가격 반응 분포, 힌트 필요 수, 차단 문제.
4. 게이트별 판정과 근거.
5. 다음 작업 결정과 이유.

동의나 결과를 미리 채우지 않습니다.
세션을 하지 않은 항목은 `[NOT_EVALUATED]`로 남깁니다.

## 8. 선례

개인 계정의 다른 프로젝트에서 다음 선례를 이식했습니다.

- quest-keeper AND-40 (2026-09-14, 미머지 브랜치): 스토어 변경 전 컨셉 인터뷰 5명, 개발자·기존 사용자만 모집 금지, 가격을 앵커로 두고 4단계 반응을 기록, 3/5 진행·2/5 거부 게이트, 시장 조사는 수요를 증명하지 않는다는 원칙.
- ttush_push 닫힌 플레이테스트 키트: 초대문에 규칙을 설명하지 않음, 플레이 후 한 번만 질문, 혼란·불공정·지루함으로 분류, 반복되는 답만 채택.
- 이 저장소의 M2-13과 [M3 명세](m3-campaign.md) §3의 원칙: 자동 비교를 사람의 재미 평가로 해석하지 않음.

베타와 지불 의사 질문을 결합한 선례와 외부 테스트 없이 출시한 게임의 사후 기록은 `[no precedent found]`였습니다.
