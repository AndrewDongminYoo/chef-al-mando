## 1. 범위와 승인 근거

운영자는 M3 설치본의 플레이를 확인한 뒤 PR #6을 머지하고, 다음 마일스톤을 서브에이전트 TDD와 `$pr-loop`로 진행하도록 요청했습니다.
이 명세는 [블루프린트](../plans/PLAN.md)의 M4 중간 저장·복원, 한국어·영어, 태블릿, 설정을 구체화합니다.
구현·로컬 검증·커밋·푸시·PR 리뷰 대응과 조건 충족 후 머지는 이번 요청 범위입니다.
기기 설치·삭제·강제 종료, 참가자 모집, 스토어 배포와 브랜치·worktree 삭제는 포함하지 않습니다.

캠페인 수량, 콘텐츠, 100 ms tick, 마감 tick 3000, 회계·예약·이동 규칙은 유지합니다.
새 엔진·외부 의존성·범용 저장 프레임워크·온라인 기능을 추가하지 않습니다.

## 2. 영업 상태와 복원

`ServiceSim.export_state()`는 표시용 이름·파생 회계·일회성 이벤트를 제외한 복원 상태를 깊은 복사로 반환합니다.
`ServiceSim.restore(data, state, preparation)`는 전체 검증을 통과한 새 simulation만 반환하며 기존 객체를 부분 변경하지 않습니다.
성공 결과는 `accepted`, `simulation`을, 실패 결과는 `accepted: false`, `reason`을 갖습니다.

복원 상태에는 tick·closed, 주문 공정·소비 여부·예약, 직원 담당·보류 담당·이동, 작업 경로·진행, 재고·전역 예약, 보류 명령·last_sequence, 대기·설비 점유 지표를 포함합니다.
현재 sim version은 seed의 산술 일정만 사용하므로 `prng_state`는 필수 `null`입니다.
이 값이 빠지거나 다른 값이면 거부합니다.
실제 가변 PRNG를 도입할 때는 sim version과 상태 계약을 함께 바꿉니다.

`ServiceSession`은 캠페인의 시나리오 ID, 준비 선택, simulation 상태, 배속, 잔여 마이크로초를 묶습니다.
준비 선택은 `purchases`, `prep_quantities`, `placements`, `duties`이며 기존 `PreparationPlan`의 시작 명령으로 다시 검증합니다.
정적 definitions·경로·주문 일정은 이 선택과 시나리오에서 재구성합니다.
세션 복원은 저장된 캠페인 기록상 해금된 시나리오만 허용합니다.
JSON의 정수 값은 유한한 정확한 정수인지 확인한 뒤 변환하며 분수·범위 초과·잘못된 타입을 거부합니다.

로드는 다음 관계도 검사합니다.

- 주문은 해당 tick까지 도착한 일정의 정확한 순서와 ID·메뉴·기한을 갖습니다.
- 모든 enum·재료·직원·설비·작업 ID와 공정 범위가 유효합니다.
- 직원·주문·작업은 일대일로 연결되고 설비와 작업 위치가 중복 예약되지 않습니다.
- 경로는 정적 장애물을 통과하지 않는 인접 격자이며 경로 인덱스·직원 위치·이동 진행이 서로 맞습니다.
- 주문별 예약 합은 전역 예약과 같고, 전역 예약은 현재 재고를 넘지 않습니다.
- 최초 준비 재고에서 실제 소비를 뺀 값이 현재 재고와 같습니다.
- 종료 주문에는 활성 작업·예약이 없으며 매출은 제공 주문에서 다시 계산합니다.
- 보류 명령의 적용 tick은 현재 tick 이후이며 sequence는 고유하고 last_sequence 이하입니다.
- 마감 상태는 tick 3000이며 미완료 작업·예약·보류 명령이 없습니다.

복원한 영업은 항상 일시정지 상태입니다.
배속은 `1`, `2`, `4` 중 저장한 값이며 미완료 tick 미만의 잔여 시간은 보존합니다.
화면 명령 sequence는 복원한 last_sequence에서 이어집니다.
이미 소비한 이벤트나 효과음은 다시 재생하지 않습니다.
마감 상태를 복원하면 결과를 표시하며 완료 기록 반영은 중복 호출에도 같은 결과를 유지합니다.

## 3. 단일 저장 파일과 호환성

아래는 M4 도입 당시 계약입니다.
2026-09-09에 승인한 [메뉴별 기본 우선순위](menu-priorities.md)는 새 쓰기를 schema 3으로 확장하며 schema 1·2 읽기를 유지합니다.

기존 `user://campaign_records.json`을 단일 권위 파일로 유지합니다.
schema 2는 `schema_version: 2`, `content_version: 1`, `sim_version: 1`, `records`, `active_session`을 갖습니다.
`active_session`은 위 세션 또는 `null`입니다.
M3 schema 1은 읽을 때 `active_session: null`로 해석하며, 읽기만으로 파일을 다시 쓰지 않습니다.
성공한 다음 쓰기에서만 schema 2로 전환합니다.
2026-09-10 캠페인 운영 압력 변경은 새 쓰기의 `content_version`을 2로 올립니다.
콘텐츠 버전 1은 읽기만으로 원본을 바꾸지 않고 완료·최고 기록을 유지하며 `active_session`을 새 규칙에서 다시 시작하도록 `null`로 해석합니다.
이전 목표로 완료한 기록에는 `legacy_completed` 표식을 붙이며, 새 목표를 달성하면 표식을 제거합니다.
2026-09-11 자동 정책 검증과 난이도 조정은 새 쓰기의 `content_version`을 3으로 올립니다.
콘텐츠 버전 2는 완료·최고 기록을 그대로 유지하고 진행 중 영업을 `null`로 해석하며, 다음 정상 쓰기에서 버전 3으로 갱신합니다.
`load_records()`와 `save_records(records)`의 기존 호출은 유지합니다.
records만 저장하는 호출은 기존 active session을 보존해야 합니다.
`save_active_session(session, records)`는 둘을 한 번에 교체하고, `clear_active_session()`은 기록을 유지한 채 session만 `null`로 저장합니다.

임시 파일 쓰기·재읽기 검증·마지막 정상 백업·주 파일 교체는 기존 저장소의 한 경로를 사용합니다.
임시 파일을 정상 세이브처럼 자동 채택하지 않습니다.
주 파일이나 백업의 알 수 없는 미래 버전은 모든 쓰기·복구로부터 보호합니다.
손상되거나 복구가 필요한 파일은 자동 초기화하지 않습니다.
백업 복구는 명시적 버튼을 통해 진행하고, 복구 불가 시 원본을 보존한 저장 없는 새 세션을 명시적으로 선택할 수 있습니다.

저장 시점은 준비 완료 직후, 마지막 자동 저장부터 100 game tick 이상 지난 첫 프레임 종료 경계, 일시정지·배경 전환, 명시적 목록 이동, 마감입니다.
저장을 생명주기 콜백에만 맡기지 않습니다.
저장 실패는 이유와 재시도를 표시하고 현재 결과·세션을 유지합니다.
실패한 저장을 숨긴 채 다른 영업으로 이동하지 않습니다.
목록으로 돌아가기는 저장 후 이어하기를 남기고, 이를 버리고 새 영업을 시작하는 동작은 명시적으로 확인합니다.
시나리오 재시작은 같은 준비 선택과 새 예산·재고로 시작하며 이전의 진행 중 상태를 원자적으로 교체합니다.

## 4. 언어와 설정

기본 언어는 한국어이며 지원 locale은 `ko`, `en`입니다.
기존 한국어를 원문으로 사용하는 Godot 기본 translation catalog와 `tr()` 경로를 사용합니다.
stable ID와 simulation 상태는 번역하지 않습니다.
목록·브리핑·준비·주문·대기 사유·결과·엔딩·저장 오류·확인창·설정의 사용자 문구와 콘텐츠 이름을 모두 번역합니다.
언어 변경은 현재 화면과 동적 버튼을 즉시 갱신하며 simulation tick·명령·결과를 바꾸지 않습니다.

설정은 언어, 효과음 켜기·끄기, 글자 크기 기본·크게 두 단계입니다.
큰 글자는 기본의 120%이며 Control 전체를 확대하지 않고 실제 font size를 바꿉니다.
캠페인과 영업 화면 양쪽에서 설정을 열 수 있고, 영업 중 열면 일시정지합니다.
설정창을 닫거나 앱 포커스가 돌아와도 자동으로 영업을 재개하지 않습니다.
설정 파일은 게임 세이브와 별도이며 정확한 키·타입·지원 값을 검증합니다.
임시 파일 검증 후 교체하고, 실패를 표시하며 알 수 없는 미래 설정 파일을 덮어쓰지 않습니다.
설정 복원 검사는 실제 파일을 읽는 새 객체와 새 실행을 사용합니다.

## 5. 화면과 효과음

폰은 접이식 상세, 태블릿은 병렬 상세를 유지합니다.
캠페인·브리핑·설정도 폰의 좁은 가로 화면과 태블릿의 4:3 화면을 각각 검증합니다.
태블릿을 폰 화면의 단순 확대판으로 만들지 않습니다.
필수 동작은 탭으로 가능해야 하며 기본 최소 탭 높이 64와 안전 영역을 유지합니다.
긴 영어 문구와 큰 글자는 스크롤·줄바꿈·패널 배치로 처리합니다.
고정 시간 제어, 실제 조작 대상, 잘림 없는 중요 문구를 별도로 확인합니다.

제품 효과음은 주문 접수·제공 완료·경고의 짧은 원본 cue 세 가지입니다.
프로젝트의 Python 표준 라이브러리 WAV 생성 소스에서 재현 가능하게 만들고 출처를 기록합니다.
외부 음원·음성·배경 음악·음성 합성 서비스를 추가하지 않습니다.
Godot 기본 AudioStreamPlayer와 버스 제어를 사용하며 반복 경고는 제한합니다.
포커스 상실·배경 전환 때 효과음을 중단하고 복귀만으로 재생하지 않습니다.
사용자의 시작·재개 뒤 새 이벤트에만 반응합니다.
효과음과 애니메이션은 simulation 결과를 결정하지 않습니다.

새 검사는 먼저 의도한 실패를 확인하고, 문법 오류나 없는 fixture만으로 TDD를 통과했다고 기록하지 않습니다.

렌더링은 `--locale=ko` 또는 `--locale=en`, 선택적 `--large-text`, `--phone-wide` 또는 `--tablet`의 여덟 조합을 실행합니다.
`--negative-layout`와 `--negative-input`에서 해당 속성 검사 실패를 먼저 확인합니다.
운영자가 화면 검사의 작업 방해를 알리고 헤드리스 실행을 요청한 이후에는 위 렌더링 명령을 다시 실행하지 않습니다.
기존 렌더링 증거는 보존하고, 후속 Godot 실행은 버전 확인과 자식 프로세스를 포함해 `--headless`를 사용합니다.
새 렌더링 실행은 운영자가 별도로 요청할 때 재개합니다.
실기기에서는 저장 후 앱 종료·이어하기, 통화/알림/권한창 중단과 수동 재개, 두 언어·글자 크기·안전 영역을 별도 확인해야 합니다.
