# 영업 피드백 명세

## 1. 목적

플레이어가 영업 중 직원의 현재 행동과 병목을 읽고, 마감 뒤 프렙·발주·메뉴 우선순위 중 무엇을 바꿀지 관측 근거로 판단할 수 있게 합니다.
이 명세는 기존 고정 시나리오, 공정, 배치 제약, 저장 형식과 시뮬레이션 결과를 유지합니다.
마이크 입력, 음성 인식, 새 권한 요청은 추가하지 않습니다.

## 2. 실시간 직원 상태

각 직원은 배정된 주문의 메뉴, 현재 공정, 이동 목적을 항상 표시합니다.
직원 상태 문구는 다음 상태를 구분합니다.

- 프렙 재료를 받으러 재료 보관대로 이동합니다.
- 원재료를 받으러 재료 보관대로 이동합니다.
- 프렙 재료 또는 원재료를 챙깁니다.
- 손질 결과물을 받으러 이동합니다.
- 새 원재료를 손질하러 이동하거나 손질합니다.
- 냉식대 또는 화구로 이동하거나 조리합니다.
- 완성된 요리를 받으러 이동합니다.
- 제공대로 운반하거나 제공합니다.

주방 위 직원에는 메뉴 아이콘과 현재 공정 배지를 함께 표시합니다.
색상만으로 상태를 구분하지 않습니다.
프레젠테이션은 스냅샷의 주문, 작업, 직원 정보를 읽어 문구와 배지를 만들며 시뮬레이션 결과를 결정하지 않습니다.

## 3. 요리사 말풍선

말풍선은 상태 전환이나 문제 발생 때만 표시합니다.
한 번에 가장 중요한 말풍선 하나를 표시하고 같은 종류의 반복은 제한합니다.
말풍선은 실제 시간 약 2초 동안 유지하며 배속과 무관하게 읽을 수 있어야 합니다.

다음 사건을 지원합니다.

| 사건           | 표시 예시                   | 근거                                                 |
| -------------- | --------------------------- | ---------------------------------------------------- |
| 재료 부족 시작 | `으악, 재료가 없어!`        | 주문이 처음 `missing_ingredients` 대기에 들어갑니다. |
| 프렙 재고 소진 | `구이 프렙 다 썼다!`        | 준비 재료 한 인분을 소비한 직후 해당 재고가 0입니다. |
| 완성 뒤 만료   | `다 만들었는데 가버리셨어!` | `serve` 공정에 도달한 주문이 기한 때문에 종료됩니다. |

긴 이동 불평은 임의 거리 기준으로 만들지 않습니다.
이동이 실제 병목이라는 근거가 없는 영업에는 `화구가 멀다` 같은 원인 문구를 표시하지 않습니다.

## 4. 마감 분석

마감 화면은 기존 손익과 누적 시간보다 먼저 `다음 영업에서 바꿀 것`을 표시합니다.
제안은 관찰, 해석, 행동의 세 부분을 포함하고 최대 3개만 표시합니다.
실제로 바꿀 수 있는 제안을 먼저 표시하고, 이미 상한에 도달한 선택은 상한 사실과 대신 확인할 병목을 표시합니다.

### 4.1 프렙

메뉴마다 선택한 프렙 수량, 사용 수량, 남은 수량, 생재료 손질 주문 수를 집계합니다.
남은 프렙이 있으면 다음 영업에서 줄일 수량을 제안합니다.
프렙이 소진되고 생재료 손질이 발생했으며 준비 노동량이 남으면 추가할 수량을 제안합니다.
준비 노동량이 가득 찼으면 프렙을 더 만들라는 제안을 하지 않고, 남은 다른 프렙을 옮길 수 있는지 또는 다른 병목을 확인하라고 표시합니다.

### 4.2 발주

구매 가능한 재료마다 발주량, 영업 종료 잔량, 사용량을 표시합니다.
관련 메뉴가 재료 부족으로 기다렸고 종료 잔량이 0이면 발주 부족 후보로 표시합니다.
여러 재료가 필요한 메뉴에서는 특정 재료가 유일한 원인이라고 단정하지 않고, 해당 메뉴의 부족 시간과 종료 시점의 0 재고를 함께 표시합니다.
남은 재료는 줄일 수 있는 발주 후보로 표시하되 메뉴 판매 가능성 검증을 우회하지 않습니다.
종료 재고와 재료 부족이 모두 0이면 비용이 가장 큰 사용 재료를 표시하고, 발주량보다 운영 병목을 먼저 바꾸라고 안내합니다.

### 4.3 메뉴 우선순위

메뉴마다 준비 화면의 기본 우선순위, 제공 수, 미제공 수, 작업대 대기와 담당 직원 작업 중 시간을 집계합니다.
미제공 주문이 있고 경합 시간이 있으며 우선순위가 2보다 낮으면 우선순위를 올릴 후보로 표시합니다.
우선순위가 이미 2이면 더 올리라고 제안하지 않고 작업대, 담당 직원, 이동 중 가장 큰 관측 병목을 표시합니다.

## 5. 데이터 경계

`sim/service_analysis.gd`는 콘텐츠 정의, 최종 서비스 스냅샷, 준비 선택을 받아 구조화된 분석 결과를 반환합니다.
분석 결과는 식별자와 숫자로 구성하며 현지화된 문장을 포함하지 않습니다.
`sim/service_sim.gd`는 기존 주문 종료 사건을 확장하고, 재료 부족 진입과 프렙 소진을 새 사건으로 발행합니다.
이벤트는 결정성 해시와 저장 상태에 포함하지 않습니다.
`presentation/main.gd`와 `presentation/kitchen_board.gd`는 구조화된 상태와 사건을 현지화하여 표시합니다.
기존 저장 스키마는 변경하지 않습니다.

## 6. 접근성과 화면 규칙

직원 상태 문구는 기존 직원 영역을 사용합니다.
공정 배지는 기존 메뉴 아이콘과 짧은 공정 기호를 사용합니다.
말풍선은 주방 사각형 안으로 위치를 제한하고 직원이나 설비를 장시간 가리지 않습니다.
휴대폰, 태블릿, 기본 글자, 큰 글자 조합에서 잘림과 겹침을 확인합니다.

## 7. 검증

- 같은 입력에서 분석 결과와 최종 상태 해시는 `1x`와 `4x`가 같아야 합니다.
- `hot_queue`에서 구이 프렙 4개와 기본 우선순위 2를 선택하면 프렙 또는 우선순위를 더 올리라는 불가능한 제안을 하지 않아야 합니다.
- 프렙 잔량, 생재료 손질, 재료 부족, 우선순위 경합 fixture가 각 제안 분기를 실행해야 합니다.
- 재료 부족, 프렙 소진, 완성 뒤 만료 이벤트는 같은 상태가 이어지는 동안 반복 발행되지 않아야 합니다.
- 직원 상태는 `pickup`, `prep`, `cook`, `serve`의 이동과 작업을 구분해야 합니다.
- M2, M3, M4 전체 gate가 통과해야 합니다.
