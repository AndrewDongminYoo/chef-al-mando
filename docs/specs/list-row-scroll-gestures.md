# 목록 행 스크롤 제스처

작성일: 2026-09-14.
상태: 로컬 구현 및 검증 완료.

## 1. 문제

홈의 영업 목록과 게임 화면의 주문 목록에서 손가락을 행 내부에서 움직이면 스크롤이 시작되지 않습니다.
행 사이의 빈 공간에서 시작한 제스처만 상위 `ScrollContainer`에 전달됩니다.
이 때문에 사용자는 목록이 스크롤되지 않는다고 느끼거나, 스크롤을 시작할 좁은 빈 공간을 찾아야 합니다.

## 2. 목표

영업 행과 주문 행 위에서 시작한 세로 드래그가 해당 목록을 스크롤하게 합니다.
짧은 탭은 기존처럼 행을 한 번 선택해야 합니다.
드래그가 행 선택으로 처리되면 안 됩니다.

## 3. 범위

이번 변경은 다음 두 목록의 일반 `Button` 행만 다룹니다.

1. 홈 화면의 영업 선택 목록.
2. 게임 화면의 주문 목록.

준비 화면의 선택 컨트롤, 마감 분석, 라이선스 문서, 시뮬레이션 규칙, 저장 형식과 콘텐츠는 변경하지 않습니다.
전체 버튼 테마나 공통 버튼 생성기의 입력 정책도 변경하지 않습니다.

## 4. 입력 계약

목록 행은 마우스와 터치 입력을 계속 받아 탭 동작을 수행합니다.
처리되지 않은 포인터 이동은 상위 `ScrollContainer`까지 전달해야 합니다.
상위 컨테이너가 드래그를 스크롤로 판정하면 행의 눌림 상태를 취소해야 합니다.

## 5. 수용 기준

| ID     | 요구사항                                                                            | 검증                                                                                      |
| ------ | ----------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| LRS-01 | 홈의 영업 행에서 시작한 세로 드래그가 영업 목록의 `ScrollContainer`에 전달됩니다.   | 실제 캠페인 장면의 영업 행에 터치 드래그를 전달하는 M3 UI 회귀 테스트로 확인합니다.       |
| LRS-02 | 게임의 주문 행에서 시작한 세로 드래그가 주문 목록의 `ScrollContainer`에 전달됩니다. | 20개 주문 fixture의 실제 주문 행에 터치 드래그를 전달하는 M3 UI 회귀 테스트로 확인합니다. |
| LRS-03 | 드래그는 행을 선택하지 않고, 짧은 탭은 행을 정확히 한 번 선택합니다.                | 같은 실제 행의 `pressed` 횟수를 드래그와 탭 뒤에 각각 확인합니다.                         |
| LRS-04 | 기존 캠페인, 시뮬레이션, 저장과 현지화 동작에 회귀가 없습니다.                      | `scripts/check.sh m4`가 실패 없이 끝나는지 확인합니다.                                    |

## 6. 검증 한계

자동 테스트는 두 목록의 Godot 입력 전달, 드래그 중 선택 방지와 짧은 탭을 확인합니다.
Headless display server는 터치 드래그를 모바일 관성 스크롤로 변환하지 않으므로 스크롤 좌표 변화 자체는 확인하지 않습니다.
일상 사용 중인 iPhone과 Android 실기기에서의 손가락 감각은 별도 기기 설치와 관찰 전까지 확인되지 않은 상태로 둡니다.
