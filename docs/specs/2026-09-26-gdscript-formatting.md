# GDScript 포맷과 린터 도입 명세

## 목적과 범위

운영자가 승인한 GDScript 설정 커밋, 린터 활성화, reformat PR을 진행합니다.
`quality-configs`의 gdtoolkit 정의를 사용하며 플러그인은 `v0.10.0`, `gdformat`과 `gdlint`는 `4.5.0`에 고정합니다.
`v0.9.0`에는 해당 정의가 없어 플러그인 참조 갱신이 필요합니다.
새로운 게임 동작, 콘텐츠, 저장 스키마, 모바일 배포는 범위에 포함하지 않습니다.

## 설정과 예외

루트 `gdformatrc`와 `gdlintrc`는 120열을 사용합니다.
기존 guard clause와 큰 UI·검사 파일을 그대로 유지하기 위해 `max-returns`와 `max-file-lines`는 비활성화합니다.
반복 리소스 로드, 긴 문자열·측정 주석, 기존 선언 순서의 예외는 코드에 `gdlint` 지시자로 한정합니다.
다른 위치에서는 해당 규칙이 계속 적용됩니다.
`.trunk/trunk.yaml`의 `lint.ignore`는 Godot·빌드·Android 생성물을 두 도구에서 제외합니다.

`tests/fixtures/content_limits.gd`는 `gdformat 4.5.0`이 파일 문서 주석을 딕셔너리 내부로 복제하므로 포맷터만 제외합니다.
이 파일의 역사적 데이터와 주석은 유지하며, 기존 긴 데이터 행은 파일 단위 `max-line-length` 예외를 적용합니다.
`gdlint`의 다른 규칙과 콘텐츠·저장 호환 검사는 계속 실행합니다.
이 예외는 주석 보존 검사를 통과하는 도구 버전에서 제거를 검토합니다.

## 파싱 불가 파일 정책

파싱 오류는 검사 실패로 처리합니다.
파일 전체를 무시하거나 파싱 오류 규칙을 끄지 않습니다.
현재 두 `== not` 표현은 같은 의미의 `== (not ...)`으로 작성하여 파싱할 수 있게 합니다.
새 문법이 도구보다 앞서 도구에서 처리할 수 없는 경우에는 Godot의 파싱 결과와 최소 재현을 먼저 확인하고 별도 결정을 받습니다.

## 완료 기준

- Trunk가 두 린터와 프로젝트 설정을 읽습니다.
- 의도적인 규칙 위반과 파싱 오류가 실제 검사 실패로 드러납니다.
- 추적 중인 GDScript 경로만 포맷하고 재실행 시 추가 변경이 없습니다.
- 파싱 가능한 파일의 포맷 전후 트리와 기존 주석을 보존합니다.
- 기존 headless suite, Python 재시작 검사와 export 검사를 통과합니다.
- 실제 pre-commit·pre-push 훅, 현재 PR head의 CI와 호스팅 리뷰 결과를 확인합니다.

## Upstream 제출 조건

`trunk-io/plugins` 제출은 이 설정과 reformat PR 머지 이후에 검토합니다.
pre-commit·pre-push에서 1–2주간 거짓 도구 실패나 누락된 문제가 없어야 하며, 파싱 불가 파일 처리 정책을 검토해야 합니다.
이번 PR은 이 기간의 관찰 결과를 대신하지 않습니다.
